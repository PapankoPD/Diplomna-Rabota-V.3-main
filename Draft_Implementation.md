# 6. Реализация на софтуерното решение

## 1. Използвани технологии и среди за разработка
Програмният код на системата е реализиран изцяло със съвременни технологии, базирани на JavaScript екосистемата:
* **Сървърна част (Backend):** Използвана е средата Node.js заедно с Express.js. Базата данни е имплементирана чрез SQLite3 с използване на синхронизирани SQL заявки. Управлението на автентикационните токени е реализирано с библиотеката jsonwebtoken.
* **Клиентска част (Frontend):** Потребителският интерфейс е създаден с React.js. Използвани са React Router за клиентско маршрутизиране и съвременни CSS модули за стилизиране, съобразени с актуалните уеб стандарти.
* **Среда за разработка:** Проектът е написан в редактора Visual Studio Code, като запазването на версиите е осъществено чрез системата за контрол на версиите Git.

## 2. Структура на проекта и основни модули
Проектът е разделен физически в две основни папки, обслужващи двете части на клиент-сървър архитектурата:

Директорията `src/` съдържа сървърната част, структурирана в логически модули: папка `routes` за дефиниране на крайните точки (API endpoints) на системата, папка `controllers` за бизнес логиката (автентикация, управление на материали) и папка `middlewares` за междинен софтуер (софтуер за валидиране на JWT и управление на качените файлове чрез `multer`). Важни помощни функции, като тези за търсене, са изнесени в `utils/`.

Клиентското приложение (Single Page Application) се намира в `client/src/`, където са разделени компонентите за многократна употреба (`components/`), основните страници като UploadMaterialPage и MaterialDetailPage (`pages/`) и логиката за извиквания на HTTP заявки чрез axios (`api/`). За поддръжка на глобално състояние на автентикацията се използва React Context API.

## 3. Ключови фрагменти от кода
За да се подсигури висока производителност при търсене сред десетки материали, е използван модул за пълнотекстово търсене (Full-Text Search - FTS5) в SQLite. По-долу е представен ключов фрагмент от сървърната логика (`search.js`), който демонстрира изграждането на динамична SQL заявка:

```javascript
const queryParams = [searchQuery];
let baseQuery = `
  SELECT m.*, bm25(materials_fts) as rank
  FROM materials m
  JOIN materials_fts fts ON m.id = fts.rowid
  WHERE materials_fts MATCH ?
`;
if (filterVisibility) {
  baseQuery += " AND m.is_public = 1";
}
baseQuery += " ORDER BY rank LIMIT 20";
```

Този фрагмент показва как сървърът приема ключова дума, асоциира я с FTS5 виртуалната таблица `materials_fts` и чрез функцията `bm25` (вграден алгоритъм за оценка по релевантност) връща най-подходящите резултати.

Друг ключов фрагмент е свързан с поддръжката на множество файлове към един учебен материал (`materials.js`). Контролерът обработва масива от файлове, предоставен от външната библиотека, и записва съответните метаданни:

```javascript
const files = req.files;
files.forEach(file => {
  const insertStmt = db.prepare(
    `INSERT INTO material_files (material_id, file_name, file_path, file_size)
     VALUES (?, ?, ?, ?)`
  );
  insertStmt.run(materialId, file.originalname, file.filename, file.size);
});
```

Това решение позволява гъвкавост, тъй като към едно заглавие (или конспект) могат да се добавят колкото е необходимо учебни ресурси (например PDF лекция и отделен ZIP архив едновременно).
